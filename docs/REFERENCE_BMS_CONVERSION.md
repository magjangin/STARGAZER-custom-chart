# BMS → STARGAZER 차트 변환 규칙

구현: [`src/Bms/BmsChart.cs`](../STARGAZER%20custom%20chart/src/Bms/BmsChart.cs) (순수 파서),
[`src/Bms/BmsChartInjector.cs`](../STARGAZER%20custom%20chart/src/Bms/BmsChartInjector.cs) (게임 주입).

파서는 게임/Harmony/Unity 의존성이 없어 단독으로 검증할 수 있습니다.

## 전체 흐름

```
BMS 텍스트
  └─ BmsChart.TryParse       마디별 노트 목록(분수 위치 + 노트 종류)
                             + 음원 오프셋 반영, 시간순 정렬, 롱노트 짝 검증
       └─ TryInjectBmsChart  마디마다 Area 생성 → Note 추가 → 전부 성공하면 Layer.Areas 교체
```

주입은 `StargazerPlayer+INNER_PatternLoader._Load_b__5_0(Pattern)` 시점에 일어납니다.
게임이 원본 패턴을 다 읽은 직후이며, 이때 원본 노트 하나(아무 노트나 첫 번째)를 **템플릿**으로 삼아
`Note` / `Area` / `BeatInfo` / `NoteProperty`의 실제 IL2CPP 타입을 얻습니다.
그래서 원본 패턴 로딩은 반드시 성공해야 합니다.

이 주입은 로그 설정(`EnableRuntimeProbeLogging`)과 무관하게 커스텀 곡이면 항상 돕니다.

## 위치 매핑 — 분수 그대로

BMS는 마디 안 위치를 `i/N`으로 적습니다(`N`은 그 채널 데이터의 슬롯 개수).
게임의 `BeatInfo`도 `BeatIndex / BeatSplit` 분수라서, **초 단위 변환 없이 분수 대 분수로 직접 옮깁니다.**

```
beatIndex   = (슬롯 번호 × 마디 비트 수) / GCD
beatSplit   = (슬롯 개수)               / GCD
```

시간으로 환산했다가 되돌리지 않으므로 부동소수점 오차가 생기지 않습니다.

- `Area` 하나 = 마디 하나(4/4 기준 4비트). 2026-07-09 실측으로 확정([WORKLOG_03](WORKLOG_03_AREA_STRUCTURE_AND_BMS_INJECTION_2026-07-09.md)).
- 새 `Area`의 `length`는 **4비트로 명시**합니다. 분모는 원본 곡 Area와 같게 맞춥니다(원본 `192/48` → `192/48`).
  예전처럼 템플릿 Area의 `length`를 그대로 복사하면 원본 곡 첫 마디가 4비트가 아닐 때 모든 마디가 틀어집니다.
- 새 Area를 **전부 만든 뒤에만** 기존 `Layer.Areas`를 비웁니다. 중간에 하나라도 실패하면 원본 차트를 그대로 둡니다
  (한 마디만 빠져도 뒤 마디가 전부 당겨져 싱크가 어긋나기 때문).
- `BeatInfo`는 **그 노트가 속한 Area 시작점 기준 상대 위치**입니다.
- `Area.Duration`, `KickIntervalTime`은 읽기 전용이라 건드리지 않습니다. 엔진이 `AreaBPM`+`length`로 계산합니다.

## 채널 ↔ 레인 매핑

| BMS 채널 | `Layer.Lanes` 순번 | 방향 |
| --- | --- | --- |
| 16 | 0 | 위 |
| 12 | 1 | 아래 |
| 13 | 2 | 왼쪽 |
| 11 | 3 | 오른쪽 |

코드에서는 `BmsChannelLaneOrder = { 16, 12, 13, 11 }`이며, 이 배열 순서가 `Layer.Lanes[0..3]`의
물리 배치(위/아래/왼쪽/오른쪽, 실측)에 대응합니다. 16 기준 시계 방향(위→오른쪽→아래→왼쪽)으로 11, 12, 13을
오름차순 배정한 것입니다.

> 이전 판의 이 표는 12=오른쪽, 13=아래, 11=왼쪽으로 적혀 있었는데, 같은 문서의 "배열 순서 = 위/아래/왼쪽/오른쪽"
> 설명과도, 실제 코드 동작과도 맞지 않는 오기였습니다. 위 표가 코드의 실제 동작입니다.
>
> 11/12/13 중 어느 것이 실제 화면의 오른쪽인지는 오름차순 **가정**이라 게임에서 확인이 필요합니다.
> 주입할 때 `[BmsInject] 채널→레인 매핑: 16->L?(위), 12->L?(아래), ...` 로그가 실제 LaneUID와 함께 한 번 찍힙니다.
> 다르면 `BmsChannelLaneOrder` 배열만 바꾸면 됩니다.

실제 `LaneUID` 문자열(`L0`, `L1`…)은 곡마다 다를 수 있어 **하드코딩하지 않고 런타임에 `Layer.Lanes`에서 순서대로 조회**합니다.

매핑에 없는 채널의 노트는 건너뛰고, 완료 로그에 `skippedByChannel=N(channels=...)`으로 개수를 남깁니다.

## 무시하는 채널

| 채널 | 의미 | 상태 |
| --- | --- | --- |
| 01 | BGM 자동재생 | 노트로는 무시. 단, 곡 음원 위치는 오프셋으로 반영(아래 "곡 음원 시작 위치") |
| 02 | 마디 길이 변경 | **미지원** — 모든 마디를 4/4로 고정 |
| 03, 08 | BPM 변경 | **미지원** — `#BPM` 헤더 하나만 사용 |
| 09 | STOP | **미지원** |

곡 중간에 BPM이나 박자가 바뀌는 차트는 아직 정확히 변환되지 않습니다.
차트에 이런 채널이 있으면 주입할 때 `[BmsInject] 지원하지 않는 기능이 차트에 있습니다: ...` 경고가 나옵니다.

### 기본 BPM

기본 BPM은 **`#BPM 값`** 형태(뒤에 공백/탭)만 읽습니다.
`#BPM01 180` 같은 줄은 채널 08이 참조하는 BPM 변경용 정의라 무시합니다.
예전에는 이 줄도 기본 BPM으로 읽혀서, 마지막 정의 값이 곡 전체 BPM을 덮어써 싱크가 통째로 어긋났습니다.

## 곡 음원 시작 위치 (채널 01)

게임은 곡 음원(`music.ogg`)을 차트 0초에 재생합니다. 그런데 BMS에서는 음원을 채널 01의 BGM 오브젝트로
원하는 위치(예: `#00101`)에 놓을 수 있습니다. 그래서 파서는:

1. `#WAV` 정의 중 **파일 이름이 앨범 음원 파일 이름과 같은 것**(대소문자 무시)을 찾고,
2. 채널 01에서 그 ID가 처음 나오는 위치를 음원 시작점으로 삼아,
3. 모든 노트를 그만큼 앞으로 당깁니다(분수 연산이라 오차 없음). 음원 시작보다 앞의 노트는 버립니다.

음원이 `#000` 맨 앞에 있으면 아무것도 바뀌지 않습니다. 적용되면 로그가 남습니다.

```
[BmsInject] 채널 01의 곡 음원이 4비트(1마디) 지점에서 시작해 노트를 그만큼 앞으로 당겼습니다.
```

## 파일 인코딩

BOM(UTF-8/UTF-16) → 엄격한 UTF-8 → CP949 순으로 판별합니다. 한국어 BMS 에디터가 CP949로 저장해도
`#WAV` 파일 이름의 "시작"/"끝"이 깨지지 않습니다(`hold start`/`hold end` 같은 영문 이름은 인코딩과 무관).

## 확장 사운드 ID (3자리)

BMS는 원래 사운드 ID를 36진수 2자리로 씁니다. 1296개를 넘기면 3자리를 쓰는 확장 포맷이 있습니다.

- **판별**: `#WAV` 헤더의 ID 부분이 3글자면 확장 포맷으로 간주합니다.
- 확장 포맷이면 노트 데이터도 2글자가 아니라 **3글자씩** 잘라 읽습니다.
- 잘라낸 값의 앞자리가 `0`이면 떼어내 기존 2자리 체계로 정규화합니다(`002` → `02`).

```
#WAV001 normal.wav      ->  id 01
#WAV002 hold 시작.wav   ->  id 02
#WAV003 hold 끝.wav     ->  id 03
#WAV016 music.ogg       ->  id 16

#00512:000002000000000003000000    3글자씩: 000 002 000 000 000 003 000 000
```

## 롱노트

**사운드 ID 번호가 아니라 `#WAV` 파일 이름으로 판별합니다.** 번호를 바꿔도 의미가 유지되게 하기 위해서입니다.

| 파일 이름 조건 | 노트 종류 | 게임 `NoteProperty.linked` |
| --- | --- | --- |
| `hold` + (`시작` 또는 `start`) | HoldStart | `StartPoint` |
| `hold` + (`끝` 또는 `end`) | HoldEnd | `EndPoint` |
| 그 외 | Normal | `None` |

대소문자는 구분하지 않습니다. 분류 결과는 주입 시 로그로 남습니다.

### 짝 검증

짝이 깨진 `StartPoint`/`EndPoint`는 게임에서 무결성 오류(크래시)를 냅니다
([WORKLOG_02](WORKLOG_02_NOTE_RUNTIME_FINDINGS_2026-05-08.md)). 그래서 파서가 **레인(채널)별로 시간순으로** 짝을 맞추고,
짝이 없는 마커는 일반 노트로 바꿉니다.

- 시작이 열린 채로 또 시작이 오면 → 앞의 시작을 일반 노트로
- 열린 시작 없이 끝이 오면 → 그 끝을 일반 노트로
- 곡 끝까지 닫히지 않은 시작 → 일반 노트로

같은 채널이 여러 줄에 나뉘어 있어도 마디 안 노트를 먼저 시간순으로 정렬하므로 짝이 올바르게 맞춰집니다.

```
[BmsInject] 짝이 맞지 않는 롱노트 마커 N개를 일반 노트로 바꿨습니다
```

```
[BmsInject] 사운드 ID 분류: 01=Normal, 02=HoldStart, 03=HoldEnd, 16=Normal
[BmsInject] 완료: ... notesCreated=553(hold 3시작/3끝) ...
```

짝 검증 뒤에도 시작과 끝 개수가 맞지 않으면(정상이라면 일어나지 않음) 경고가 나옵니다.

홀드가 마디를 넘어가면 시작과 끝이 서로 다른 `Area`에 들어갑니다.
게임 원본 차트도 인접 Area에 짝이 나뉘어 있는 것이 관측되어 같은 방식으로 두었으나,
**마디를 넘는 홀드는 아직 실제로 검증되지 않았습니다.**

## 노트 사운드에 대해

게임의 `Note`에는 "이 노트가 어떤 소리를 낸다"는 필드가 없습니다.
타격음은 게임의 SFX 시스템(`SoundPlayer.PlaySFX`)이 고정으로 처리합니다.

따라서 변환기는 **그 자리에 노트가 있는지 없는지**만 보면 되고,
BMS의 키음(`normal.wav` 등)은 게임에서 재생되지 않습니다.
사운드 ID는 롱노트 판별 용도로만 읽습니다.
